# Deploying EntityGraph

Written for someone who does not want to think about servers. Roughly fifteen
minutes, most of it waiting.

## Why not Vercel

Vercel hosts websites that answer a request and finish. This is a long-running
data pipeline with a database:

- **Builds take 5–30 minutes.** Vercel stops a request after 13 minutes at
  most, 1 minute on the free plan. A build would be killed partway through.
- **The database is a file on disk.** Vercel's filesystem is temporary and
  per-request, so the corpus and its scores would be erased between page loads.

Render runs an ordinary always-on server with a disk attached, which is what
this app already is. Railway and Fly.io work the same way if you prefer them.

## One-time setup

**1. Create the service.** Sign in at [render.com](https://render.com), choose
**New → Blueprint**, and pick this repository. Render reads `render.yaml` and
fills in everything except the secrets.

**2. Paste the secrets** when Render asks. These are the same values as your
local `.env`:

| Key | Where it comes from |
|---|---|
| `DATAFORSEO_LOGIN` | your DataForSEO account email |
| `DATAFORSEO_PASSWORD` | the **API password** at app.dataforseo.com/api-access — not your website login |
| `ANTHROPIC_API_KEY` | console.anthropic.com → API Keys |
| `BOOTSTRAP_ADMIN_EMAIL` | the email you want to sign in with |

`SESSION_SECRET` is generated by Render. Do not set it by hand, and do not
change it later — every signed-in session breaks if you do.

**3. Wait for the first deploy,** then open the deploy log and find:

```
┌─ First run ────────────────────────────────────
│  Sign in as: you@yourfirm.com
│  Password:   <generated once>
└────────────────────────────────────────────────
```

That password appears **once** and is never recoverable. Sign in with it
immediately; you will be asked to choose your own.

## After that

Every push to `main` redeploys automatically, usually in under a minute. That
is the whole workflow — edit, push, live.

Your data lives on the mounted disk at `/var/data`, so it survives deploys and
restarts.

## Costs

| | |
|---|---|
| Render Starter instance | ~$7/month |
| 1 GB disk | ~$0.25/month |
| DataForSEO and Anthropic | per build, against the ceilings you set |

The free Render tier cannot be used: it has no disk, and it sleeps after
inactivity, which would kill a build in progress.

## Backing up

The database holds every build you have paid for. Rebuilding it costs real
money, so it is worth a copy:

```bash
curl -u you@yourfirm.com https://your-app.onrender.com/api/entities > backup.json
```

For the full file, use Render's shell (**Dashboard → Shell**):

```bash
cp /var/data/entitygraph.db /var/data/backup-$(date +%F).db
```

Render disks are not automatically backed up. If the data matters, take a copy
before any risky change.

## Things worth knowing

**A build survives a redeploy badly.** Deploying restarts the process, and any
job running at that moment is marked failed. The corpus and evidence already
written are kept, so a rebuild resumes cheaply — but avoid pushing while a
build is running.

**One build at a time.** The queue is deliberately serial. Two builds of one
entity cannot interleave and corrupt each other's scores.

**Scaling past one instance would break things.** The job queue and login
throttling live in the process's memory. If you ever need more than one
instance, the queue has to move to the database first.
